## 1. 背景与核心痛点调研

### 1.1 现状与痛点

当前 `koishi-plugin-theme-lxgw-wenkai`（v0.2.0）定位为单纯的 **Koishi 控制台 WebUI 主题插件**。其核心逻辑仅通过 `ctx.console.addEntry()` 向控制台客户端注入预打包的 CSS 与 JS 模块。

然而，在对 `koishi-dev-8` 真实开发环境的深层扫描与启动日志排查中，发现了极其严重的**跨插件字体冗余与生态碎片化问题**：

```text

2026-11-17 00:46:11 [I] who-at-me-vincentzyu ✅ 默认字体已存在且 hash 校验通过，跳过下载...
2026-11-17 00:46:14 [I] messageCounter 已加载 1 个可用字体文件。
2026-11-17 00:46:17 [I] wydashen-guangyi-query 🔍 开始检查默认字体: G:\...\data\fonts\LXGWWenKaiMono-Regular.ttf
2026-11-17 00:46:18 [I] not-just-cf [字体] LXGWWenKaiMono-Regular.ttf 已存在且校验通过。
2026-11-17 00:46:18 [I] youtube-vincentzyu-fork ✅ 默认渲染字体已存在且 hash 校验通过，跳过下载...
```

1. **重复造轮子与网络浪费**：
   至少有 7 个主流出图插件（`sky-renwu-weibo`、`billboard-data`、`cs-lookup`、`picstatus`、`messageCounter`、`who-at-me`、`wydashen-guangyi-query` 等）都在各自编写几十行的网络下载与 Hash 校验逻辑，各自在后台去下载一份 30MB 左右的霞鹜文楷完整 TTF 字体，易发生网络超时（如常见的 `timeout of 20000ms exceeded`）。
2. **独立 Web 扩展与大屏无法复用**：
   第三方独立推流与 Web 扩展（例如 `http://localhost:8498/` 赛博博弈竞技场大屏端、OBS 直播间透明覆盖层）无法复用控制台的主题字体和现代化配色，样式处于孤立状态。
3. **缺少中央统一服务**：
   Koishi 生态中缺乏一个标准的 **Typography & Theme Service（排版与视觉服务）**，导致“出图排版”和“控制台样式”两者割裂。

## 3. 配置项设计与 Schema 规范

为了遵循 Koishi 的渐进式演进理念，避免默认行为破坏现有纯净控制台体验，**将全局 Context 服务与 Puppeteer 自动 Hook 分别抽象为两个独立的实验性开关**，默认均为关闭状态，并显式标注 `.experimental()`。

### 3.1 Schema 定义规范

```typescript
export interface Config {
  // === 原有主题配色配置 ===
  colorPreset: 'default' | 'lxgw-blue' | 'lxgw-autumn' | 'custom'
  customLightColor?: string
  customDarkColor?: string

  // === 实验性特性 1：全局 Context 服务 ===
  enableService?: boolean
  serveExternalWeb?: boolean
  externalWebPort?: number

  // === 实验性特性 2：无感 Hook Puppeteer ===
  autoHookPuppeteer?: boolean
  targetSelectors?: string
}

export const Config: Schema<Config> = Schema.intersect([
  // ... 既有基础配色 Schema ...

  Schema.object({
    enableService: Schema.boolean()
      .default(false)
      .experimental()
      .description('启用全局 Context 字体与主题服务 (注册 ctx.themeLxgw，供其他插件和独立网页调用)'),
  }).description('全局服务设置 (Service Infrastructure)'),

  Schema.union([
    Schema.object({
      enableService: Schema.const(true).required(),
      serveExternalWeb: Schema.boolean()
        .default(true)
        .description('通过 Koishi 内置 HTTP 服务暴露跨域字体与 CSS (供 8498 独立大屏 / OBS 浏览器源使用)'),
      autoHookPuppeteer: Schema.boolean()
        .default(false)
        .experimental()
        .description('实验性黑魔法：自动 Hook 全局 ctx.puppeteer.page，所有插件出图无感自动注入霞鹜文楷'),
    }),
    Schema.object({}),
  ]),
])
```

在 Koishi WebUI 的配置页面中，这两个开关将会优雅地附带金黄色的 `实验性` 徽章，既显现专业度，又保障现有用户的稳定性。

## 4. 架构技术方案深度设计

### 4.1 方案 A：注册标准 Cordis 服务（`ctx.themeLxgw`）

#### 4.1.1 类型声明与接口契约
在 TypeScript 中扩展 Koishi 上下文：

```typescript
import { Context, Service } from 'koishi'

declare module 'koishi' {
  interface Context {
    themeLxgw: ThemeLxgwService
  }
}

export interface ThemeLxgwService {
  /** 本地完整字体的绝对路径（单例缓存，供 node-canvas、Skia 或 SVG 绘图使用） */
  readonly fontPath: string
  /** 适用于 HTML 模板内嵌的 @font-face CSS 代码片段 */
  readonly fontFaceCSS: string
  /** 当前主题的主色调 Hex */
  readonly primaryColor: string
  /** 获取字体的二进制 Buffer */
  getFontBuffer(): Promise<Buffer>
  /** 为传入的 Puppeteer Page 手动注入霞鹜文楷与字体继承规则 */
  injectPage(page: any): Promise<void>
}
```

#### 4.1.2 服务实现类
基于 `Service` 基类实现，仅在 `config.enableService` 开启时挂载：

```typescript
export class ThemeLxgwServiceImpl extends Service implements ThemeLxgwService {
  static inject = { optional: ['server', 'puppeteer', 'console'] }

  private _fontPath: string = ''

  constructor(ctx: Context, public config: Config) {
    super(ctx, 'themeLxgw', true)
    this._fontPath = this.resolveOrInitLocalFont()

    // 挂载外部 HTTP 访问路由
    if (config.serveExternalWeb && ctx.server) {
      this.initHttpRoutes(ctx)
    }

    // 执行自动 Hook（若开启）
    if (config.autoHookPuppeteer && ctx.puppeteer) {
      this.initPuppeteerHook(ctx)
    }
  }

  get fontPath(): string {
    return this._fontPath
  }

  get fontFaceCSS(): string {
    return `
      @font-face {
        font-family: 'LXGW WenKai Mono';
        src: url('file://${this.fontPath.replace(/\\/g, '/')}') format('truetype');
        font-weight: normal;
        font-style: normal;
        font-display: swap;
      }
    `
  }

  async injectPage(page: any): Promise<void> {
    if (!page || typeof page.addStyleTag !== 'function') return
    await page.addStyleTag({
      content: `
        ${this.fontFaceCSS}
        * {
          font-family: 'LXGW WenKai Mono', -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif !important;
        }
      `
    })
  }

  // ... 字体下载单例与 HTTP 路由实现 ...
}
```

### 4.2 方案 B：外部 WebUI（如 `localhost:8498` 大屏）HTTP 跨域接入设计

#### 4.2.1 源码实现机制
在 Koishi 内置服务 `@cordisjs/plugin-server`（Koa）上动态注册路由：

```typescript
private initHttpRoutes(ctx: Context) {
  // 1. 静态样式路由：/fonts/lxgw-wenkai.css
  ctx.server.get('/fonts/lxgw-wenkai.css', async (koaCtx) => {
    koaCtx.set('Access-Control-Allow-Origin', '*')
    koaCtx.set('Access-Control-Allow-Methods', 'GET, HEAD, OPTIONS')
    koaCtx.set('Content-Type', 'text/css; charset=utf-8')
    koaCtx.set('Cache-Control', 'public, max-age=86400')

    koaCtx.body = `
      @font-face {
        font-family: 'LXGW WenKai Screen';
        src: url('/fonts/lxgw-wenkai/font.woff2') format('woff2');
        font-display: swap;
      }
      :root {
        --font-lxgw: 'LXGW WenKai Screen', sans-serif;
        --theme-primary: ${this.config.customDarkColor || '#38bdf8'};
      }
    `
  })

  // 2. 托管字体文件
  ctx.server.static('/fonts/lxgw-wenkai', dirname(this.fontPath))
}
```

#### 4.2.2 消费端（如 8498 对战大屏 / OBS 浏览器源）调用范式
只需在独立网页的 HTML 中引入：
```html

<style>
```

### 4.3 方案 C：终极无感黑魔法 —— 全局 Hook `ctx.puppeteer.page`

#### 4.3.1 原理剖析
在 Cordis 的依赖注入体系中，Service 挂载在 Context 原型链上。通过拦截 `ctx.puppeteer.page` 方法，对其进行 Proxy 包装，即可在任意插件调用 `await ctx.puppeteer.page()` 获取页面实例后，**透明挂载导航监听钩子**。

#### 4.3.2 严密防御与平稳卸载设计
为了保证热重载（HMR）以及插件卸载时不发生内存泄漏或原型污染，必须严格登记 `dispose` 恢复机制：

```typescript
private initPuppeteerHook(ctx: Context) {
  ctx.inject(['puppeteer'], (scopedCtx) => {
    const puppeteer = scopedCtx.puppeteer
    const originalPage = puppeteer.page.bind(puppeteer)

    // 1. 包装 page 工厂方法
    puppeteer.page = async (...args: any[]) => {
      const page = await originalPage(...args)

      // 监听 DOM 加载事件（兼容 setContent 与 goto）
      page.on('domcontentloaded', async () => {
        try {
          if (!page.isClosed()) {
            await this.injectPage(page)
          }
        } catch {
          // 页面瞬态关闭时忽略
        }
      })

      return page
    }

    // 2. 插件卸载/热更新时优雅还原，严禁残留
    scopedCtx.on('dispose', () => {
      puppeteer.page = originalPage
    })
  })
}
```

#### 4.3.3 生态受益场景
一旦开启该选项：
- `sky-renwu-weibo`（每日光遇任务出图）无需在模板写字体定义；
- `billboard-data`（术力口周榜出图）直接获得高清文楷水墨质感；
- `cs-lookup`（饰品战绩查询出图）自动消除 Linux Docker 下的字体小方块；
- 所有插件**无需更改任何一行源码**，即可获得全域统一的优雅排版。

## 6. 约束与安全红线（Safety Guardrails）

1. **零侵入默认原则**：
   `enableService` 与 `autoHookPuppeteer` 必须默认为 `false`。未显式开启时，插件表现必须与现有 v0.2.0 完全一致，仅作为纯净 WebUI 控制台主题运行。
2. **生命周期原子性**：
   所有对 `ctx.puppeteer`、`ctx.server` 的拦截与挂载，必须在 `scopedCtx.on('dispose', ...)` 中 100% 幂等复原，严禁污染其他运行中插件。
3. **字体存储规范**：
   单例字体存放必须遵循统一约定（优先复用 `data/fonts/LXGWWenKaiMono-Regular.ttf`），避免向系统目录写入无权限文件。
